# 应付清单管理测试用例说明

## 测试概述

为应付清单管理的CRUD方法编写了完整的集成测试用例，覆盖应付清单主表和明细表的全部业务操作。

## 测试文件

**文件路径**: `app-ais-export-vehicle-start/src/test/java/com/leapmotor/export/vehicle/payablelist/service/PayableListServiceTest.java`

| 4 | testGetPayableListById_notExists | 根据ID查询 - 不存在的ID | 抛出业务异常，消息包含"应付清单不存在" |

| 9 | testAddVehicles_normal | 批量添加车辆 - 正常添加 | 不抛异常（当前为TODO） |
| 10 | testRemoveVehicles_normal | 删除车辆 - 正常删除 | 不抛异常（当前为TODO） |
| 11 | testImportPrice_normal | 导入最新价格 - 正常导入 | 返回导入结果，包含成功/失败数量 |
| 12 | testDeletePayableListByIds_normal | 删除应付清单 - 正常删除 | 返回true，删除后查询抛异常 |
| 13 | testDeletePayableListByIds_emptyList | 删除应付清单 - 空列表 | 返回false |
| 14 | testDeletePayableListByIds_nullList | 删除应付清单 - null列表 | 返回false |

| 16 | testPagePayableList_searchByCustomerName | 分页查询 - 按客户名称模糊查询 | 返回包含关键字的记录 |
| 17 | testPagePayableList_searchByVin | 分页查询 - 按VIN查询 | 不抛异常（关联明细表查询） |
| 18 | testPagePayableList_searchBySubmitTime | 分页查询 - 按提交时间范围查询 | 返回时间范围内的记录 |
| 19 | testPagePayableList_searchByConfirmTime | 分页查询 - 按确认时间范围查询 | 返回时间范围内的记录 |
| 20 | testDeletePayableListByIds_batch | 删除应付清单 - 批量删除 | 批量删除多条记录成功 |

**关键验证点**:

- **数据完整性**: ID、编号、状态等关键字段不为null
- **业务规则**: 草稿状态才能提交、版本号校验、状态流转正确
- **异常处理**: 不存在的记录抛异常、非法操作抛异常
- **并发安全**: 乐观锁版本号递增机制
- **分页逻辑**: 分页大小限制、总数统计准确

## 运行测试

### 运行所有测试

```bash
mvn test -pl app-ais-export-vehicle-start
```

### 运行单个测试类

```bash
# 运行应付清单主表测试
mvn test -pl app-ais-export-vehicle-start -Dtest=PayableListServiceTest

# 运行应付清单明细测试
mvn test -pl app-ais-export-vehicle-start -Dtest=PayableListDetailServiceTest
```

### 运行单个测试方法

```bash
mvn test -pl app-ais-export-vehicle-start -Dtest=PayableListServiceTest#testPagePayableList_normalQuery
```

## 测试数据准备

测试用例依赖于数据库中已有的测试数据。建议在测试环境准备以下数据：

1. **应付清单主表**: 至少包含草稿状态和已提交状态的记录
2. **应付清单明细表**: 至少包含多条明细记录，关联到不同的应付清单
3. **测试数据特征**:
   - 不同的单据状态（草稿、已提交、已确认等）
   - 不同的客户信息
   - 不同的时间范围（创建时间、提交时间、确认时间）
   - 已收款和未收款的明细记录

## 注意事项

1. **测试顺序**: 使用 `@Order` 注解控制测试执行顺序，某些测试依赖前置测试的结果
2. **数据清理**: 测试会修改数据库状态，建议在独立的测试数据库运行
3. **TODO方法**: `queryAvailableVehicles`、`addVehicles`、`removeVehicles` 当前实现为TODO，测试仅验证不抛异常
4. **并发安全**: 提交操作测试验证了乐观锁版本号机制
5. **业务规则**: 测试覆盖了状态流转规则（草稿→已提交）
